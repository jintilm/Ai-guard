        • 流式无法撤回：内容已经发出去了，只能末尾补一条告警帧 + 审计， 审计 note 里写明「无法撤回」，不要把它读成已拦住。
        • 只认结构化格式：不扫 api_key = xxx 这类自由文本形态 —— 那在代码与文档里太常见，扫它等于自造过防御。

          正在连接本地检测服务…
          当前是静态快照，检测台未连接服务。
          本页由 python -m prompt_ids.web 生成，双击打开时不带后端 —— 这是有意为之： 离线也能看实验数据、也能直接交作业。
          要动手试，改成本地服务模式启动：
          python -m prompt_ids.web --serve --semantic （--semantic 可选，加上才启用语义层；不加就是规则层 + 启发层，毫秒级）
          启动后浏览器会自动打开同一个页面，检测台即可用。也可以直接调 REST 接口 POST /v1/scan（见 prompt_ids --probe 与 GET /v1/openapi.json）。
          判定口径 high / critical 记预测攻击并阻断；medium 转人工复核。分层耗时、未执行层、 缓存命中与截断状态都会显示 —— 只看一个总分容易得出错误结论。
          审计只落指纹 检测台写入审计的是文本指纹而非原文，和命令行、代理、REST 完全同一套规则。
          批量口径 每行一条，最多 200 条；走的是与单条、命令行、代理完全相同的四级流水线与审计， 结果按等级分布汇总，便于一眼看出这批文本的可疑比例。
          两段各扫一次，并排看判定与命中项的差异（分数升高＝更可疑）
          复核闭环 「确认攻击 / 标记误报」会写入审计事件（只含指纹）并喂回向量记忆层 —— 标记误报即写入负向记忆，同类文本下次分数会被压下去。 这条回路是误报治理的入口：没有它，误报只能靠用户投诉发现。
          需要原文，且原文不进日志 审计层只存指纹（这是刻意的隐私约定），所以队列无法直接展示内容： 复核时需要你把原文粘进来。记忆层未启用时复核照常可用， 只是结论不影响后续判定。
          这一页扫的是输出，不是输入 前三页看的是「用户发进来的话」，出站扫描看的是「模型吐出去的话」： 第三方凭据（AWS / OpenAI / Slack / GitHub / 私钥 / JWT）不该跟着答案流出去。 代理在转发路径上会自动做同一件事（默认开启）。
          只回脱敏形态 响应里给的是类别、位置与首尾几个字符，不是完整密钥 —— 复核台账需要原文， 但凭据的原文不应该再经手一次。命中会被就地脱敏成 [REDACTED:kind]。
