## 这个系统是什么

检测 LLM 的**提示词注入**（prompt injection）—— 用户或检索到的文档试图改写
模型指令、或骗它吐出系统提示词。

判定分五级（`level`），每级映射到一个动作（`action`）：

```
safe  →  pass       无风险
low   →  log        记录
medium→  review     送人工复核
high  →  sandbox    放行 + 记审计（HTTP 200，不是拦截）
critical → block    拦截
```

⚠ **`high` 默认是 `sandbox` 不是 `block`** —— 这是最容易记错的一条：
「检测为高危」≠「请求被拒」。`sandbox` 的语义是**放行并留痕**。
统计拦截率时按 `action == "block"` 判，不要按 `level >= high` 判
（否则默认策略下会把 sandbox 算成拦截，虚报约 27%）。

## 三个层，各自负责什么

| 层 | 做什么 | 特点 |
|---|---|---|
| **L1 规则** | 83 条正则/关键字，跨中英德法西日六语种 | ~1ms、纯离线、结果可解释。**只擅长「明确的钓鱼措辞」** |
| **L2 启发** | 按类目加权打分 | 补规则的空白，抓「可疑但没命中规则」 |
| **L3 语义** | DeBERTa 或 LLM 裁判 | 抓规则抓不到的改写型注入，但慢且可能误伤 |

**关键取舍**：规则层在「角色扮演 / 任务改写」这类注入上召回接近 0
（agent 面实测 block 召回 0.0000），因为它们没有
"ignore all previous instructions" 这种钓鱼措辞。这类必须靠 L3。
反过来，L3 会把正常的 RAG 系统提示误判成注入（实测 6 条里误判 3~5 条），
所以代理对 `system` 消息**默认只走规则层**。

完整的实测数字与引用纪律见 [AGENTS.md](../AGENTS.md) 与 [README](../README.md)。
